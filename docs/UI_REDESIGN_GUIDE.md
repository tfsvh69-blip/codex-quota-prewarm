# Codex Quota Prewarm · UI 改版规范与可复用提示词

## 本次设计方向：工程工具 / Quiet Operations

这是高频查看的开发者工具。用紧凑、平静、信息准确的版式取代大卡片网格。采用浅灰背景、白色阅读区域、深海军蓝操作按钮、青绿色当前项标记；橙色只用于限制或需要注意的状态，红色仅用于失败、冲突和真正危险的操作。

Typography（字体排版）：Segoe UI / Microsoft YaHei 系统字体；主要信息 14–17px，用量数字 17–24px，重置时间 11.5–12px。数字采用 tabular-nums（等宽数字），减少刷新时跳动。

### 布局

- 页面头部只放产品名称、连接状态、刷新。
- 概览四小块：启用槽位数、可用账号数、额度满额数、当前操作槽位。
- 高亮一条当前操作账号摘要；说明 **它不会改变其它软件的账号**。
- 主区域为 **一张连续账号列表**：账号/身份、短周期与每周**剩余**、重置时间、快捷操作、可展开的运行日志。
- **同屏优先比较 A/B/C**，而不是每张卡片重复一套过大边框与说明。
- D 等停用槽位仍可找到，但用灰色弱化；未知额度没有“已用完”的错误进度条。
- 新增/启用账号与运行机制放在独立、次级区域。
- 在 1040px 以下账户行换为 3 列+操作行；680px 以下账户身份独占一行、两个额度指标并排，操作按钮换行。

## 不可妥协的业务语义

1. 「已使用 100%」不等于「登录失败」，登录身份与额度状态必须分开。
2. 用户首先看到 **剩余比例**，进度条的宽度必须等于 `100 - usedPercent`；已使用比例只作为次要信息显示。周期名称按 `windowDurationMins` 标注，不假设短周期永远是五小时。
3. `quota===null` 显示「未提供」、`usedPercent` 缺失显示「未读取」、账号停用显示停用状态与空轨道；**不能使用 0 或 100 假装数据**。
4. A 固定主账号、不可停用。B/C/D 需要能独立登录、替换和禁用，并能识别重复身份。
5. 「当前操作」仅切换本上位机当前槽位，**绝不静默切换/覆盖其它应用的登录文件**。
6. 时间一律明确按 **北京时间 (UTC+8)** 显示。
7. 上位机的刷新只查询额度，不能调用模型消耗额度。
8. 登录的 OAuth 链接不进日志和 Git；敏感凭据不出现在 UI 源码里。
9. 原计划任务、后端接口路径和端口保持兼容；无必要不改业务逻辑。
10. 动画只用必要的反馈（轻微 hover/进度），必须适配 prefers-reduced-motion。

## 可直接复用的 AI 提示词（本次已按此执行）

请作为熟悉 Windows 本地软件、Codex CLI、控制台产品设计的资深前端工程师和交互设计师，对现有 \`dashboard/index.html\`、\`dashboard/style.css\`、\`dashboard/app.js\` 进行一次 **仅 UI/交互层的工程化重构**。

项目背景：原生 HTML + CSS + JS + Node http，无 React；实际用户需要每天查看 A 主账号、B/C 可换副账号及未来 D/E 账号的 5 小时和每周额度、当前重置时间与预激活日志。接口已能工作，账号身份/定时任务是既有逻辑。

任务：
- 参考 Anthropic frontend-design、Addy Osmani frontend-ui-engineering、UI UX Pro Max 的原则，参考 Tabler 的后台布局，但不引入新框架或未授权的付费 UI。
- 先审视真实页面，明确数据主次、重复内容、失效状态与误导表达；给出语义化 design tokens（设计变量）。
- 把大而稀疏的重复账号卡片重组为紧凑、稳定、方便跨账号比较的账号列表。突出当前操作账号，额度双周期与重置时间直观可读。
- 状态必须严格区分：可用、已登录但限额、未登录、额度查询失败、身份重复、已停用。
- 账号登录/换号、当前操作、打开终端、启用停用、新增槽位、查看日志必须可操作。危险操作需要确认，失败要有可执行提示。
- 不得把未读取额度画成满进度条；不能将 REQUEST_OK 误标为“已开启新窗口”。
- 宽度 1360、866、390px 均不能水平溢出；中文邮箱长字符串要安全截断或换行；键盘 focus-visible 可见。
- 不更改 Codex 认证目录，不发起真实模型请求，不改变正在运行的 Windows 定时任务。
- 用 npm test、浏览器实际页面/截图与真实只读额度检查验收；给出变更文件、已知限制和复盘。

最终风格：成熟、克制、实用的开发者工具。避免“AI 生成感”：夸张渐变、伪科技发光、过多卡片、无意义动画、情绪化文案、巨型标题、过多边框。

## 2026-10-29 进度条显示修复

- 根因：后端 CSP 为 `style-src 'self'`，原来的 `<div style="width:56%">` 内联宽度遭浏览器拦截；百分比文本正确，但彩色填充退化为默认块级宽度 100%。
- 修复：使用原生 `<progress max="100" value="剩余百分比">`，以外部 `style.css` 中的 `::-webkit-progress-value` 和 `::-moz-progress-bar` 控制颜色；保留原有严格 CSP，不开放 `unsafe-inline`。
- 回归测试：强制检查前端无旧 `meter-fill` 内联宽度逻辑，测试 0%、16%、44%、64%、70%、100% 已用对应的剩余值。
- Edge 浏览器实际截图验收：A 的 46% / 28% 进度条分别填充对应长度，B/C 的 0% 无彩色填充，C 的 84% 每周额度只填充 84%。截图测试仅用于本机验证，不进入版本库。

## 2026-10-29 账号排序与重置时间显示

- 列表按最早预计可用时间展示，不修改 `accounts.json` 槽位顺序、账号标识、登录凭据和当前操作账号；只排序渲染用的数组副本。
- 已登录且官方已知额度可用的账号排在前面；额度耗尽时取所有耗尽周期 `resetsAt` 的最大值（最后一道限制解除），按时间从早到晚排列。`ordinaryUsageAllowed=false` 可能只是五小时额度耗尽造成，不能阻止预测该周期的恢复顺序。
- 重置时间已过但额度仍显示耗尽，标注“重置时间已到，待刷新”，不能直接当作已恢复；其他限制、登录异常、缺失时间保持待确认；停用账号最后。同时间按槽位字母顺序，避免刷新时跳动。
- 每个额度区域用 `<time datetime>` 加独立的日期/秒级时间标签呈现，样式来自外部 CSS，不放宽 CSP；额度耗尽使用暖色，未读取显示空状态。UI 保留北京时间 (UTC+8) 提示。
- 浏览器实测顺序 A → C → B → D（测试时 C 18:13:38 恢复，B 20:47:56 恢复）；回归测试覆盖双周期耗尽、查询异常、普通限额返回 `allowed=false` 和不修改原始账号数组。

## 2026-10-29：倒计时与操作区精简

- 需求：不再让用户根据重置时间手算剩余时长；移除进度条，以两个时间卡片分别展示短周期、每周额度重置倒计时。小号文本显示剩余额度和预计北京时间重置时刻。
- 倒计时：从官方 `resetsAt` 秒级 Unix 时间戳与浏览器 `Date.now()` 的差计算，`setInterval` 每秒仅更新倒计时文本（不每秒请求官方接口）；恢复页面可见时重新校准。显示 `HH:MM:SS` 或 `N天 HH:MM:SS`，到零显示「等待额度同步」，不能自行宣布账号额度恢复。
- 空状态：数据未读取、账号未启用或无此窗口不虚构重置时间。短周期和每周仍各自独立展示，排序规则及原始账号槽位名称保持不变。
- 快捷操作：当前账号显示不可点击的状态标识，其他可用槽位直接展示「设为当前」；更换登录、打开终端、停用账号保留在原生 `<details>`「更多操作」中；停用账号直接显示「启用账号」。保留原有确认提示、登录流程、日志、后端路由与严格 CSP。
- 验收：`npm test` 包括倒计时格式、已到期提示、跨天计算、无数据和菜单存在性；浏览器实际检查卡片、排序与折叠菜单。禁止因前端每秒更新而发出每秒网络请求。
