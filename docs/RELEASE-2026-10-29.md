本项目是非 OpenAI 官方的 Windows Codex 辅助脚本。**不增加额度、不绕过限制**；它尝试在允许时通过正常的 Codex 请求激活新窗口，会消耗正常额度。

## 运行机制

1. 一个晨间 Windows 任务启动一次脚本；脚本加载**启用**的所有账号并逐个处理，跳过登录无效或重复身份。
2. 默认在每天 05:30 首次运行，每 15 分钟补试到 11:00 左右；每个账号每日最多三次真实尝试，成功后去重，不会每次轮询都消耗额度。
3. 真正发送请求会消耗 Codex 额度；`REQUEST_OK` 表示模型回复成功，`WINDOW_VERIFIED` 表示额外查询认为重置时刻固定，二者都不能保证未来额度服务不变化。
4. 晨间与白天智能巡检是独立任务。上位机只展示额度、倒计时及账号状态；它的“设为当前”**不会**切换系统其它已打开程序的登录状态。
5. 依赖电脑开机、Windows 登录会话、可用网络/代理和三个账号有效授权。电脑休眠、注销、关机或每周额度用尽时无法保证 05:30 实际成功。

## 在现役电脑上核对（不要重新安装第二套任务）

打开 Windows PowerShell：

```powershell
Get-ScheduledTask | Where-Object TaskName -like '*Codex*' |
  Select-Object TaskName, State
Get-ScheduledTask | Where-Object TaskName -like '*0530*' |
  Get-ScheduledTaskInfo | Select-Object LastRunTime, NextRunTime, LastTaskResult
```

在**现役安装目录**执行以下只读/无消耗检查（不是下载仓库目录）：

```powershell
node .\morning-real-prewarm.js --dry-run
node .\morning-real-prewarm.js --dry-run --account=C
```

检查现役目录内的 `logs/晨间真实预激活.log` 和 `logs/morning-A.json`、`morning-B.json`、`morning-C.json`；不要将这些日志上传公开仓库。第二天早上需看到新日期 `accounts=A,B,C`，并分别核查三个账号的状态。

## 全新 Windows 电脑安装（不要覆盖现役配置）

前提：Windows 10/11、Node.js 20+、官方 Codex CLI 和三个独立 ChatGPT 登录身份。

```powershell
npm install -g @openai/codex
# 从仓库或发布 ZIP 解压目录进入项目
Copy-Item .\config.example.json .\config.local.json
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\login.ps1 -Account A
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\login.ps1 -Account B
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\login.ps1 -Account C
npm test
node .\src\morning-real-prewarm.js --dry-run
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-dashboard.ps1
```

`install.ps1` 只管理新命名的 `Codex-Prewarm-*` 任务。如电脑已有旧版 `Codex-双账号-*` 任务，**不要直接并行安装**，先规划停用/迁移，否则可能造成重复模型请求。已有本项目任务更新时使用 `-ReplaceExistingTasks`，勿覆盖其他项目任务。
